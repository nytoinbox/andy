## Overview

- Dark theme with animations; bilingual English / Thai.

## Language switching (i18n)

- Translatable elements carry `data-i18n="key"`; English text stays in the HTML as the fallback.
- Translations live in the `i18n` object at the top of `assets/js/main.js` (`en` and `th`).
- `applyLang()` swaps text, sets `<html lang>`, saves the choice in `localStorage`, and restarts the typed hero roles (`hero.roles` is an array).
- Thai-specific typography is in CSS under `html[lang="th"] ...` (sans-serif headings, no italics, no letter-spacing).
- When adding text: add `data-i18n` in the HTML **and** a key in both `en` and `th`.

## Adding gallery images

Add a `<figure class="g-item">` with an `<img loading="lazy">` and a `<figcaption data-i18n="gallery.cN">` to `.gallery-grid`, plus caption keys in both languages.
Grid is 3 columns on desktop: `.g-wide` spans 2 columns, `.g-tall` spans 2 rows. Check the layout has no holes at desktop, ≤1000px (2 cols, `.g-tall` disabled) and ≤560px (1 col).
Strip EXIF metadata from new photos (re-save with Pillow) so no GPS data is published.

## Hero Spatial Scene

- iPhone-style "Spatial Scene" on the hero photo: a WebGL shader in `spatialScene()` (`assets/js/main.js`) shifts each pixel by `chef-depth.png`, so the chef and sushi board separate from the background.
- Driven by the mouse (desktop), device tilt (phones), or a slow idle sway after 2.5 s without input.
- iOS needs motion permission from a tap, so `.motion-btn` ("Tap for 3D") shows only where `DeviceOrientationEvent.requestPermission` exists.
- Tuning uniforms: `uStrength` (amount of shift), `uFocus` (depth that stays still, 0–1), `uZoom` (crop margin that hides edges).
- Falls back to the plain `<img>` if WebGL or the images fail, and is skipped with `prefers-reduced-motion`.
- If `chef.jpg` is replaced, regenerate the depth map with `tools/make_depth.py`, or the effect will be misaligned.

## Behaviour notes

- Contact form posts JSON to FormSubmit (`https://formsubmit.co/ajax/chinyaandy@gmail.com`, `FORM_ENDPOINT` in `main.js`), which emails the owner; visitor's address is set as reply-to and a copy goes to `nytoinbox@gmail.com` via `_cc` (`FORM_CC`; FormSubmit has no BCC). Free, no account.
  - The first submission triggers an activation email to that inbox; nothing is delivered until the owner clicks the link.
  - Hidden `_honey` field filters bots. On failure the form shows the email address as a fallback.
  - After activation FormSubmit offers a random alias to replace the address in the endpoint, if the owner wants it hidden from page source.
- `prefers-reduced-motion` disables the loader, particles, cursor effects and most transitions.
- Custom cursor / magnetic buttons / tilt only run on fine pointers (not touch).
